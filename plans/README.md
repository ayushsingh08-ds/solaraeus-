# plans/

The planning tournament's record. Four planners compete on one brief; exactly one is eliminated per round; the survivor becomes `PLAN.md`.

## Why a tournament and not an argument

Four agents with the same remit converge on the same plan unless diversity is enforced by rule. So each plan declares a **strategy family**, no two plans in a round may share one, and the arbiter sends a colliding plan back to re-plan from a different family. Elimination is scored, not voted, and the record of what lost is kept — the losing ideas are the cheapest research the project will ever get.

## The competitors

| Agent | Owns | Research entry point |
| :--- | :--- | :--- |
| `planner-a` | The whole project | Systems and GPU ray-tracing literature |
| `planner-b` | The whole project | Urban-climate validation literature |
| `planner-c` | The whole project | Product, interface and urban-practice literature |
| `planner-d` | The whole project | Publication, reproducibility and data-scarcity route |
| `planner-arbiter` | The rules and the record | Scores, eliminates, finalizes |

The entry points are where each planner *starts reading*; they are not responsibility slices. Every planner must plan the whole thing, and the differences that matter are the ones they invent.

## The rubric

Each axis is scored 0–3 with a written evidence line. Weighted total out of 42.

| Axis | Weight | A 3 looks like |
| :--- | :--- | :--- |
| Feasibility | ×3 | Every step gated, every dependency with a fallback, nothing resting on data that may not exist |
| Scientific defensibility | ×3 | Every claim maps to a measurement or an opened citation; the novelty claim survives the free-tool prior art |
| Sourcing integrity | ×2 | Every external claim has a live URL and a date, or is honestly tagged `unverified` |
| Engineering risk | ×2 | The riskiest component is de-risked first, with the CPU path as oracle and a GPU-free CI path |
| Interface and deliverable clarity | ×2 | The 3D tool and the paper each have a testable definition of done |
| Measured cost claims | ×2 | Speed and memory are benchmarks against a named baseline on one machine, never estimates |

## The rounds

Round 1 runs four planners, round 2 runs three, round 3 runs two, and the survivor of round 3 becomes `plans/PLAN.md` after the three eliminated planners have red-teamed it. Three rounds maximum, then the arbiter finalizes — a tournament with no cap never ends.

A survivor's revision must *improve*: absorb the best of the eliminated plan, add at least one newly researched element, and move at least two rubric axes with evidence. The improvement gate is checked by the arbiter and recorded, not assumed.

## The record

```
plans/
  BRIEF.md        the question every planner answers
  TEMPLATE.md     the shape every plan must have
  r1/ r2/ r3/     one file per planner per round, planner-a.md … planner-d.md
  SCORES.md       every score with its evidence line and every elimination with its reason
  INDEX.md        generated by scripts/plan_index.py
  PLAN.md         the surviving plan, with rejected alternatives and red-team notes
```

Nothing is deleted or rewritten. An eliminated plan stays in its round folder forever, exactly as rulings are never edited in `roasts/`. A changed mind is a new round, not an edit.

## Keeping it honest

```bash
python scripts/plan_index.py            # regenerate INDEX.md from the round folders
python scripts/plan_index.py --check    # exit 1 on drift, exit 2 on a malformed plan
```

`pytest tests/test_plan_log.py` runs the same checks, so a plan with no strategy family, a sourcing ledger line with no URL and no `unverified` tag, a score table whose arithmetic does not add up, a trail that skips a round, or a plan marked eliminated in one place and competing in another all fail the suite rather than quietly rotting.

## After the tournament

`plans/PLAN.md` is handed to `/roast`, which attacks it as an idea. A plan that survives both the tournament and the roast council is the plan that gets built.
